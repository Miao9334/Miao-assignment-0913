# Why Are We Here?

## Introduction About Myself
Before I start answering the question "Why are we here" (Programming Course), I would like to first answer "why I am here" (IME) by briefly introducing my background. During my undergraduate studies, my major was Graphic Design / Visual Communication Design. At the beginning, before I entered university, I thought graphic design was a very useful subject, because it can send information to people in a direct way through the arrangement of text, patterns and colours.

However, during my studies, especially as technology kept improving, flat expression seemed to be full of limits and restrictions in many ways. It cannot make the audience feel immersed, and so it cannot further activate the interaction of the audience's senses. All ideas start from flat expression, but they are also confined to it. Therefore, I think my current level of technical skills has started to limit my creative expression. That is why I chose IME.

## My Experience On Programming
While preparing my portfolio for applications, I also came into contact with code. It was an art installation, and I wanted to use a touch sensor to control the switch of an LED strip. Since I had no related experience before, I worked out a rough plan by looking up information and talking with AI: use Arduino with an Uno board to connect the sensor and the LED strip. During this process, I asked AI to generate the code and import it into Arduino, but when it came to connecting the sensor and the LED strip, I could not guarantee that every experiment would succeed. I knew the problem was probably in the coding, but I could not understand the code at all, and this really troubled me. In the end, I asked a friend who had relevant knowledge for help, and the problem was finally solved.

To sum up from this project, I think AI can indeed help us write code, but if we want to make sure a project goes smoothly, we，as designers / artists still need to master programming knowledge: to read the code, find the mistakes, and fix them.

## Code As An Artform
After class, I watched the YouTube video The Art of Code by Beattie (2020). If I had not been told in advance that many of the examples in the video were generated by code, I would probably have guessed that they were made with Adobe Illustrator, or generated by AI tools. However, there is a slight difference: in graphic design, using traditional software like Adobe Illustrator means that we are creating visuals inside a toolbox and graphical interface that someone else has already set up, and using natural language to give prompts to AI basically leaves the logic of generation to the computer. By contrast, writing code requires us to interact directly with the logic and rules of the computer.

So I think code is not just a technical tool, but also a highly expressive and dynamic medium. When I draw with code, I am no longer simply drawing a static visual form. This approach fills the gap between abstract design intention and precise visual execution, and at the same time broadens the boundaries of artistic expression. 

## Conclusion
All in all, in the first programming class, when I was asked to answer the question "Why Are We Here", I would have answered based on my past experience: programming is a tool that can help us realise our ideas. However, after taking two programming classes and doing practical work in the tutorials, my answer has changed: programming is not just a tool. It is highly expressive in itself. Therefore, we need to learn and explore it with a more respectful attitude, and gradually push beyond the boundaries of what we know.
